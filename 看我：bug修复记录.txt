Bug 1：章节内容互相污染（恶性 bug，v1.2.2 修复）
症状：快速切换章节时，其他章节的内容被错误替换或清空。例如章节1变成章节3的内容，空章节变成某章节的内容。
复现：快速连续点击不同章节

排查过程：
1. 先怀疑数据库层 → 排查后发现每章独立存储，schema 没问题
2. 怀疑 Editor 的 hasFocus 守卫 → 移除后发现不是根因
3. 添加调试日志 → 发现 selectChapter 中 doSave 保存到了错误的章节
4. 写 Playwright 自动化测试复现 → 确认根因

根因（两层问题）：
1. React 状态 current 是批量更新的 — 快速连续调用 selectChapter 时，current 还是更早的值（React 还没来得及 re-render），导致 doSave(current, contentRef.current) 中 current 指向错误章节
2. 编辑器 hasFocus 守卫阻止内容更新 — Editor.jsx 的 useEffect([value]) 有 if (viewRef.current.hasFocus) return，切换章节时编辑器仍有焦点，新内容不写入编辑器。用户继续输入时追加在旧内容后面，保存到了新章节

修复（ChaptersView.jsx）：
- selectChapter 中用 currentRef.current 替代 current（ref 立即更新，不等 React 渲染）
- 切换时直接同步更新编辑器内容（view.dispatch()），不依赖 useEffect 异步 dispatch
- 清除旧的 saveTimer，避免定时器在错误章节触发保存
- selectChapter 中调用 view.contentDOM.blur() 确保编辑器失焦

关键教训：React 状态（current、content）是批量更新的，在需要立即读取的场景必须用 useRef。

Bug 2：updateChapter 并发写入竞态条件（v1.2.2 修复）
症状：多个章节内容被互相覆盖。
根因：updateChapter 采用先读后写模式 — 先 SELECT 当前内容，内存合并后再 UPDATE。两个快速连续的保存调用会导致读取到过期数据，后一次写入覆盖前一次。

修复（electron/services/chapters.js、electron/services/characters.js）：
// 旧：先读后写（有竞态风险）
const cur = getChapter(id)
const next = { ...cur, ...patch }
UPDATE chapters SET 全部字段 WHERE id=?

// 新：原子 UPDATE（只更新传入的字段）
const sets = cols.filter(c => patch[c] !== undefined).map(c => `${c}=?`)
UPDATE chapters SET 变化的字段 WHERE id=?

Bug 3：人物卡片编辑不自动保存（v1.2.5 修复）

症状：选择 Ollama 本地模型后，调用时报"接口不存在"或"无法解析为JSON"。

Bug 5：地图节点无法点击选中（v1.2.5 修复）
症状：地图节点无法通过左键选中编辑，点击图标无反应。
根因：
1. SVG 节点内的 foreignObject（图标元素）拦截了点击事件，没有冒泡到外层 g 元素
2. SVG 的 onClick（清空选中）在节点点击后触发，覆盖了选中状态
3. onMouseDown 的 e.preventDefault() 阻止了后续 onClick 触发

修复（WorldMap.jsx）：
- foreignObject 加 style={{ pointerEvents: 'none' }} 让点击穿透
- 区分拖拽和点击：用 dragMoved ref 追踪是否移动超过 3px
- 节点用 onContextMenu（右键）选中，左键拖动
- 节点点击时 e.stopPropagation() 阻止 SVG 的 onClick 清空选中

Bug 6：打包版安装程序"被旧程序占用"（v1.2.1 修复）
症状：安装新版时提示旧程序正在运行，但实际已关闭。
根因：installer.nsh 中的进程检测逻辑不正确，或使用了自定义的 customCheckAppRunning 宏导致误判。
修复：恢复原始的 installer.nsh（含 taskkill 逻辑），移除 customCheckAppRunning 宏。用户需复制整个 win-unpacked 文件夹，不能只复制 exe。

Bug 7：dist 构建卡住（v1.2.1 修复）
症状：npm run dist 或 electron-builder 卡在 packaging 步骤不动。
根因：node_modules 中有重复依赖或损坏的包，导致 electron-builder 打包时卡死。另外 Electron 二进制文件下载超时也会导致卡住。
修复：删除 node_modules，重新 npm install，然后 npm dedupe 去重。如果网络超时，等待网络恢复后重试（Electron 二进制会缓存）。

通用经验总结
| 场景 | 正确做法 |
|------|---------|
| 需要立即读取最新状态 | 用 useRef 而非 React state |
| 避免闭包拿到旧值 | 用函数式 setState(prev => ...) |
| 区分拖拽和点击 | 用 ref 追踪 moved 标志，移动阈值 > 3px |
| SVG 内 HTML 元素点击穿透 | foreignObject 加 pointerEvents: 'none' |
| 数据库并发写入 | 用原子 UPDATE，不要先读后写 |
| 快速切换时保存到错误对象 | 用 ref 立即更新当前对象 ID |
| 编辑器切换章节内容不同步 | 直接 view.dispatch() 同步更新，不依赖 useEffect |

Bug：章节编辑区状态不同步 + 列表溢出（2026-08-14）
症状：
1. 编辑区顶部的章节名称输入框无法更改
2. 章节选择区的章节名称太长会突破选择区框架
3. 修改章节状态/场景/摘要/笔记后，编辑区显示不更新

排查过程：
检查 ChaptersView.jsx 的 input 绑定 → 发现 onChange 只更新 chapters 数组，没更新 current
检查 CSS 样式 → 发现 .tree-item 缺少 min-width: 0，flex 子元素无法收缩
检查其他元数据字段 → 发现状态/场景/摘要/笔记修改后都没有同步 current

根因（同一类问题）：
React 受控组件状态不一致。input 的 value 绑定的是 current.title，但 onChange/onBlur 只更新了 chapters 数组，没有更新 current 状态，导致 UI 不刷新。
Flex 布局中 .tree-item 缺少 min-width: 0，flex 子元素默认 min-width: auto 阻止收缩，长标题撑破容器。

修复（ChaptersView.jsx + index.css）：

// 1. 标题 onChange 同步 current
onChange={(e) => {
  const newTitle = e.target.value
  setChapters((l) => l.map((c) => (c.id === current.id ? { ...c, title: newTitle } : c)))
  setCurrent((c) => (c && c.id === current.id ? { ...c, title: newTitle } : c))  // 新增
}}

// 2. 标题 onBlur 同步 current
onBlur={async (e) => {
  if (!current) return
  const u = await window.api.updateChapter(current.id, { title: e.target.value || '未命名' })
  setChapters((l) => l.map((c) => (c.id === u.id ? u : c)))
  setCurrent(u)  // 新增
}}

// 3. 状态/场景/摘要/笔记修改后同步 current
onChange={async (e) => {
  const u = await window.api.updateChapter(current.id, { status: e.target.value })
  setChapters((l) => l.map((c) => (c.id === u.id ? u : c)))
  setCurrent(u)  // 新增
}}

// 4. AI 生成摘要后同步 chapters
setCurrent((c) => ({ ...c, summary }))
setChapters((l) => l.map((c) => (c.id === current.id ? { ...c, summary } : c)))  // 新增

// 5. CSS 溢出限制
.tree-item { overflow: hidden; min-width: 0; }
.sidebar { overflow: hidden; min-width: 0; }
.list-header { overflow: hidden; }

// 6. 按钮防压缩
<button style={{ flexShrink: 0 }}>...</button>

关键教训：React 受控组件的 value 绑定状态后，所有修改操作必须同步更新该状态；flex 子元素需要 min-width: 0 才能正确收缩。


Bug：打包后开发模式页面卡在加载（2026-08-14）
症状：运行 npm run dev 后页面一直显示"加载中"，无法进入首页

Bug：GBK编码文件导入乱码（v1.3.0 修复）
症状：导入 GBK/GB2312 编码的 txt 文件显示乱码。

根因：文件读取硬编码 fs.readFileSync(path, 'utf-8')，遇到非UTF-8编码就会乱码。

修复：
1. 安装 chardet（编码检测）和 iconv-lite（编码转换）
2. 新增 readTextFile(filePath) 函数：自动检测文件编码，按正确编码读取
3. 资料导入和章节导入全部改用 readTextFile

// readTextFile 核心逻辑
function readTextFile(filePath) {
  const buf = fs.readFileSync(filePath)
  const detected = chardet.detect(buf)
  const candidates = detected ? [detected] : []
  if (!candidates.includes('UTF-8')) candidates.push('UTF-8')
  if (!candidates.includes('GB18030')) candidates.push('GB18030')
  for (const enc of candidates) {
    const norm = enc.toLowerCase().replace(/[^a-z0-9]/g, '')
    try {
      if (norm === 'utf8' || norm === 'ascii') {
        const text = buf.toString('utf-8')
        if (!text.includes('\ufffd')) return text
      } else if (iconv.encodingExists(norm)) {
        return iconv.decode(buf, norm)
      }
    } catch {}
  }
  return buf.toString('utf-8')
}

关键教训：中文文件编码不统一，必须自动检测；chardet + iconv-lite 是可靠的组合。
